# Founder Sales Handbook — Pipeline, Proposals, Client Conversations

## Purpose

Define how `AG-GRO-SALES-001` turns client conversations and leads into structured offers, proposals, and delivery handoffs.

## Scope

Client intake analysis, qualification, proposal outlines, SOW drafts, pipeline status. No contract signing or payment processing by AI.

## Principles

1. **Client conversation is SSOT** — paste transcripts/forms into inbox; analyze from disk.
2. **Proposal before build** — scope doc exists before `@senior-saas-developer`.
3. **Human closes deals** — AI drafts; human sends, negotiates, invoices.

## Standards

### Pipeline stages

```text
lead → qualified → proposal_sent → won → delivery_handoff → delivered
```

### Deliverables

- Qualification notes (budget, timeline, fit)
- Proposal / SOW outline on disk
- Delivery brief for `AG-DLV-SAAS-001` or template lanes
- Memory record linking client slug to PRJ-* when spawned

## Best Practices

- Extract explicit client requirements from conversations; flag ambiguities
- Use `@founder-research` output when competitive positioning needed

## Anti-patterns

- Starting code without won stage + approved scope
- Storing client secrets in memory files
